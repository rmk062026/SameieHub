# Testing

- **Rammeverk:** xUnit (`tests/SameieHub.Tests`).
- **TDD** for forretningslogikk: test først → rød av riktig årsak → implementer → grønn → refaktorer.
- **Enhetstester** (Domain): `HousingUnitTests` (adresse, `AssignId`), `HousingUnitDetailsTests` (oppretting med bare adresse og med alle felt, oppdatering, normalisering, grenseverdier, ugyldige verdier, ingen delvis oppdatering, to eiere, aktivering/deaktivering, feilmelding uten verdi), `HousingUnitFilterTests` (søk og statusfilter), `BoardCaseTests` (opprettelse, standardverdier, UTC-krav, normalisering, grenseverdier, ugyldige endringer uten delvis oppdatering, statusregler, vedtak, valgfri møtedato og boenhetskobling, `AssignId`) og `HousingUnitServiceTests` (tjenesten mot `Fakes/FakeHousingUnitRepository`).
- **Integrasjonstester:** `Infrastructure/EfHousingUnitRepositoryTests` kjører mot ekte SQLite (ikke EF InMemory). `SqliteTestDatabase` lager en temp-fil per test via de samme migreringene som appen, og sletter den etterpå. Brukerens database i AppData berøres aldri. `RestartAsync()` simulerer omstart mot samme fil. `HousingUnitDetailsPersistenceTests` kontrollerer at alle felt, to eiere, fjerning av eier 2 og status lagres varig. `HousingUnitMigrationTests` oppgraderer en database fra første migrering med eksisterende rader og kontrollerer at de beholdes og er aktive.
- **UI-tester:** `Web/` bruker bUnit mot Razor-komponentene med fake repository (`FailableHousingUnitRepository` kan simulere databasefeil). Dekker liste (antall, sortering, filter, søk på begge eiernavn, tomtilstander), detaljside (alle felt, manglende verdier, eier 2 skjult/vist, aktivering), skjema (bare adresse, alle felt, eier 2 legges til/fjernes, feltmeldinger, retting etter feil) og databasefeil. Ikke dekket av bUnit: `?status=`-meldingen (bekreftet manuelt), rendermodus og ekte tastatur/nettleser.
- **Manuell UI-kontroll (M1D, M1E):** appen startes mot en isolert database (`Database__Path`) og styres i nettleser: registrering med to eiere og feilmelding ved feltet, detaljside, deaktivering, søk og filter, redigering med fjerning av eier 2, omstart med data intakt og mobilvisning. Personlige data brukes aldri; testdata er fiktive.
- **Arkitekturtest:** `DependencyDirectionTests` vokter avhengighetsretningen.
- **Kjøring:** `dotnet test SameieHub.slnx`. CI kjører restore, build og test ved push til `main` og pull requests.
- **Navnekonvensjon:** `Metode_Scenario_ForventetResultat`.
